# Многополевые объектные запросы

Универсальный поиск Qt поддерживает от одного до восьми условий для одного
опубликованного класса `net`. Условия выполняются непосредственно по объектной
таблице и объединяются оператором `AND`, без legacy-таблиц и mega-JOIN.

## Интерфейс Qt

На вкладке **Поиск** пользователь выбирает поле, операцию и значение, после
чего нажимает **Добавить условие**. Добавленные фильтры видны в отдельной
таблице; выбранный фильтр можно удалить. Кнопка **Найти** выполняет весь набор.

Если набор пуст, выполняется текущее условие — прежний однополевый сценарий
остаётся рабочим. Для результата выводятся ID, фрагмент, значения участвующих
полей, версия и состояние. Двойной щелчок открывает общую карточку объекта.

## Контракт репозитория

`SearchCriteria::conditions` содержит список `SearchCondition`:

- `fieldName` — физическое имя опубликованного поля;
- `comparison` — `equals`, `contains`, `greater`, `less`, `between`,
  `is_null` или `not_null`;
- `value` и `secondValue` — параметры сравнения.

Репозиторий принимает не более восьми условий. Для каждого поля он проверяет
безопасный формат идентификатора, наличие в `meta.layer_catalog` и физической
таблице, видимость в `meta.field_catalog`, PostgreSQL-тип и допустимость
операции. Идентификаторы экранируются драйвером, значения связываются как
параметры с приведением к подтверждённому типу. Лимит выдачи Qt — 200 строк,
максимально допустимый лимит репозитория — 1000.

## CLI

Однополевый синтаксис сохранён. Для нескольких условий передаётся имя класса
и повторяемый параметр `--search-condition`:

```powershell
.\tgid_app\build\Release\tgid_app.exe `
  --search-objects connect_node `
  --search-condition 'fragment_id|equals|86' `
  --search-condition 'memo|contains|проверка'

.\tgid_app\build\Release\tgid_app.exe `
  --search-objects pipe_section `
  --search-condition 'diametercondit|between|100|300' `
  --search-condition 'memo|not_null'
```

Формат условия: `field|comparison[|value[|second]]`. В PowerShell условие
следует заключать в одинарные кавычки, чтобы символ `|` не трактовался как
конвейер. Код возврата `28` означает неверный формат или число условий, `29` —
запрещённое поле, несовместимую операцию либо ошибку SQL.

## Проверка

Release-сборка проверена на новой БД: два условия по разным полям нашли ровно
одну строку, прежний синтаксис завершился успешно, неизвестное поле вернуло
код `29`, а девять условий — код `28`. Изменений данных или схемы этот шаг не
вносит; версия контракта БД остаётся 10.
