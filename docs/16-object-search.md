# Универсальный поиск объектов

Новый Qt-клиент выполняет типизированный поиск непосредственно по
опубликованным таблицам `net`. Это общий механизм для простых запросов старого
ТГИД и основа будущих эксплуатационных выборок; `public.nodes`,
`public.linesobj` и SQL-файлы с mega-JOIN не используются.

## Метаданные и интерфейс

Список классов загружается из `meta.layer_catalog`, а поля, русские подписи,
единицы, типы редакторов и справочники — из `meta.field_catalog` и системного
каталога PostgreSQL.

Вкладка **Поиск** поддерживает:

- `содержит` и `равно` для текста;
- `равно`, `больше`, `меньше`, `между` для чисел и дат;
- выпадающие значения `ref` и логических полей;
- условия `заполнено` / `не заполнено`;
- отдельное включение архивных строк;
- открытие полной карточки двойным щелчком по результату.

Выдача ограничена 200 строками. При достижении лимита интерфейс предлагает
уточнить условие.

## Безопасность запроса

`SearchRepository` дважды проверяет класс и поле по каталогу и физической
колонке `net`. Идентификаторы допускаются только в безопасном формате и
экранируются `QSqlDriver`; пользовательские значения всегда связываются как
параметры с приведением к подтверждённому типу PostgreSQL.

Поддерживаемые операции проверяются по типу. Например, сравнение порядка для
текстового поля отклоняется до выполнения динамического SQL. Геометрия и
неподдерживаемые типы в конструктор запроса не попадают.

## CLI

```powershell
.\tgid_app\build\Release\tgid_app.exe `
  --search-objects connect_node:memo:contains `
  --search-value проверка

.\tgid_app\build\Release\tgid_app.exe `
  --search-objects pipe_section:id:between `
  --search-value 1000 `
  --search-second-value 2000 `
  --search-archived
```

Имена операций: `equals`, `contains`, `greater`, `less`, `between`, `is_null`,
`not_null`. Код `28` означает неверные CLI-параметры, `29` — запрещённое поле,
операцию или ошибку запроса.

## Проверка

Интеграционный сценарий создаёт активный и архивный временные объекты и
проверяет текстовый фильтр, точное числовое сравнение, диапазон, NULL и режим
архива. Отдельно проверяются отказ для несуществующего поля и сравнение порядка
для текста. После теста удаляются объектные, реестровые и аудиторские строки.

Следующий уровень запросов — сохранённые многополевые выборки и конкретные
эксплуатационные отчёты из реестра старого ТГИД.
