# Теплопотребление последнего расчёта

Отчёт переносит три команды старого ТГИД в одну вкладку Qt:

- `aZap3` — все полученные нагрузки и расходы;
- `aZap4` — закрытые системы;
- `aZap5` — открытые системы.

Результаты читаются из `calc.pt_out`. Старые `public.PT_OUT`, `public.nodes` и
`public.calculation` не используются: идентификатор результата разрешается в
активный объектный узел через таблицы `net`, а последний расчёт выбирается из
`calc.calculation` отдельно для каждого фрагмента.

## Показатели

| Показатель | Теплопотребление, Гкал/ч | Расход, т/ч |
|---|---|---|
| Отопление, зависимое | `qotz` | `a4` |
| Отопление, независимое | `qotn` | `a5` |
| Вентиляция | `dop12` | `a6` |
| Открытое ГВС из подачи | `dop18` | `a12` |
| Открытое ГВС из обратки | `dop19` | `a13` |
| Рециркуляция открытого ГВС | `dop20` | `a14` |
| Закрытое ГВС, суммарно | `dop17` | `a15` |

Режим `all` возвращает все семь строк, `closed` — отопление, вентиляцию и
закрытое ГВС, `open` — три строки открытого ГВС. В Qt можно выбрать один
фрагмент либо суммировать последние расчёты всех доступных фрагментов.

## Проверка совместимости

На текущей мигрированной БД старый запрос через compat `public.nodes` и новый
запрос через объектные таблицы `net` обработали одинаковые 2 260 строк
последних расчётов двух фрагментов. Массив всех 14 агрегатов PostgreSQL сравнил
как полностью равный, без допуска на округление.

## Диагностический режим

```powershell
.\tgid_app\build\Release\tgid_app.exe --heat-consumption-report all
.\tgid_app\build\Release\tgid_app.exe --heat-consumption-report closed:2
.\tgid_app\build\Release\tgid_app.exe --heat-consumption-report open:1
```

Коды завершения: `0` — запрос выполнен, `40` — неверный режим или параметры,
`41` — ошибка чтения `calc`/`net`. Отсутствие расчёта для корректного фрагмента
не является ошибкой: Qt показывает понятное пустое состояние.
