# Соединение трубопроводных участков

Операция реализована для `net.pipe_section` и `net.line_plain`. Серверное
разрешение хранится в `meta.layer_catalog.can_join`; оборудование и остальные
линейные классы соединять нельзя.

## Серверный контракт

`net.join_lines(table, first_id, first_version, second_id, second_version)`
выполняет одну атомарную транзакцию:

1. блокирует обе активные строки в стабильном порядке и проверяет их
   `row_version`;
2. требует один класс, один фрагмент и ровно один общий активный
   `connect_node`; блокировка его строки в `node_reg` не позволяет параллельно
   создать новую связанную линию до завершения операции;
3. проверяет, что к общему узлу подключены только выбранные две активные линии;
4. сравнивает бизнес-атрибуты участков, исключая системные, топологические поля
   и `pipesectlength`;
5. ориентирует обе геометрии от одного внешнего узла к другому и создаёт один
   новый участок;
6. суммирует `pipesectlength`, архивирует исходные участки и общий узел.

При несовпадении атрибутов, наличии ответвления, петли, разных фрагментов или
конфликте версии вся транзакция откатывается. Физического удаления нет, поэтому
исходные объекты и история доступны в архиве.

## Qt и CLI

В Qt пользователь выбирает первую линию, включает **Соединить линии** и
щёлкает по второй. Приложение перечитывает карточку второй линии перед вызовом,
а после успешного обновления карты открывает созданный участок.

Диагностический вызов без GUI содержит версии обеих строк:

```powershell
.\tgid_app\build\Release\tgid_app.exe `
  --join-lines pipe_section:12345:4:12346:2
```

Коды завершения: `0` — успех, `22` — неверный формат, `23` — конфликт версии,
`24` — нарушение серверного правила или другая ошибка.

## Проверка

```powershell
psql -v ON_ERROR_STOP=1 -f sql/111_line_join.sql
psql -v ON_ERROR_STOP=1 -f sql/tests/test_line_join.sql
```

Тест внутри `BEGIN`/`ROLLBACK` проверяет конфликт версии, ориентацию геометрии,
суммарную длину, архивирование двух исходных линий и общего узла. Отдельный
сквозной тест Release-приложения вызывает ту же функцию через CLI и после
проверки удаляет все временные объектные и аудиторские записи.
