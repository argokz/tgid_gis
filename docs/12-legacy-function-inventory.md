## Как использовать реестр

1. Для каждой команды установить бизнес-статус: `required`,
   `optional`, `customer-specific`, `obsolete`.
2. Связать обязательные команды с SQL из JSON и целевой схемой
   `net`, `ref`, `calc`, `maintenance`, `tu` или `report`.
3. Для каждого переносимого запроса зафиксировать параметры, колонки
   результата и эталонное сравнение со старой БД.
4. Переносить не файлы по одному, а законченные пользовательские
   сценарии: команда → запрос → таблица/карта/отчёт.

## Следующий технический этап

Сначала закрывается основной сценарий редактора сети: полноценная
топология, специальные карточки и справочники. Параллельно из этого
реестра выделяется минимальный набор расчётных и эксплуатационных
запросов для схемы `calc` и первого модуля отчётов.

Универсальный параметризованный поиск по объектным таблицам уже реализован в
новом Qt-клиенте: [16-object-search.md](16-object-search.md). Он закрывает
базовые фильтры по одному полю без переноса сотен однотипных legacy SQL-файлов;
сложные многотабличные отчёты по-прежнему переносятся отдельными сценариями.

Первым законченным отчётным сценарием перенесено семейство команд
протяжённости, включая `aProtNew` для выделенных трубопроводов:
[17-pipe-length-report.md](17-pipe-length-report.md). Расчёт выполняется по
`net.pipe_section` и геометрии PostGIS, результат доступен в Qt и CSV.

Команда `aZap1 «Объём сети»` перенесена отдельным сценарием:
[21-network-volume.md](21-network-volume.md). Новый запрос точно воспроизводит
старую формулу и исключение внутренних схем, но работает только с объектными
таблицами `net`; доступны расчёт всей сети, фрагмента и выделенных участков.

Команды `aZap3`, `aZap4` и `aZap5` объединены в отчёт последнего расчёта:
[22-heat-consumption-report.md](22-heat-consumption-report.md). Все 14 старых
агрегатов сохранены с исходными единицами; режимы Qt показывают весь набор,
закрытые либо открытые системы. Источник результатов — `calc.pt_out`, узлы
разрешаются через объектные таблицы `net`.

Команда `aZap6 «Закрытые потребители»` перенесена в отдельную вкладку:
[23-closed-consumers.md](23-closed-consumers.md). Вместе с запросом в `ref`
перенесён справочник `externalcodes`, поэтому список и карточки не обращаются к
legacy `public`. Новый и старый запросы возвращают одинаковые 77 строк.

Команда `onPotNagr0 «С нулевой нагрузкой»` перенесена в отдельную вкладку:
[24-zero-load-consumers.md](24-zero-load-consumers.md). Сохранена исходная
асимметрия проверяемых полей для реальных и обобщённых потребителей. Новый
запрос работает через `net`/`ref` и точно совпадает со старым: 1 428 строк.
