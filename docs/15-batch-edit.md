# Массовое редактирование объектов

Qt-клиент позволяет атомарно изменить одно бизнес-поле у 2–500 активных
объектов одного класса. Операция работает с любым опубликованным точечным или
линейным классом и не повышает версию схемы БД: она использует существующие
`row_version`, `meta.field_catalog` и триггеры аудита.

## Выделение на карте

- обычный щелчок выбирает один объект;
- Ctrl+щелчок добавляет или исключает объект;
- при попытке добавить другой класс или другой тип геометрии начинается новый
  одиночный набор;
- выбранные узлы и линии подсвечиваются жёлтым;
- кнопка **Массово изменить** доступна от двух объектов.

После обновления фрагмента выделение сбрасывается, чтобы пользователь не
продолжал работу с устаревшим набором.

## Транзакционный контракт

Перед записью `ObjectRepository` получает актуальные пары `id:row_version` и
проверяет поле по реальному типу колонки и `meta.field_catalog`. Системные поля,
геометрия, топология, исходные идентификаторы и `subtype_src_id` исключены.

Изменение выполняется одним параметризованным запросом вида:

```sql
UPDATE net.<class> AS target
   SET <field> = CAST(? AS <validated_type>)
  FROM (VALUES (?, ?), ...) AS expected(id, row_version)
 WHERE target.id = expected.id
   AND target.row_version = expected.row_version
   AND target.removed_at IS NULL;
```

Имена таблицы и поля допускаются только после проверки каталога и экранируются
драйвером Qt; значения всегда передаются параметрами. Если число обновлённых
строк меньше выбранного, транзакция откатывается. Поэтому при конфликте нет ни
частичных данных, ни лишних записей аудита.

## CLI и проверка

```powershell
.\tgid_app\build\Release\tgid_app.exe `
  --batch-set connect_node:memo:проверка `
  --batch-objects 101:3,102:5
```

Коды завершения: `0` — успех, `25` — неверные параметры или запрещённое поле,
`26` — конфликт хотя бы одной версии, `27` — ошибка записи.

Интеграционная проверка создаёт два временных объекта, обновляет оба, сверяет
версии и две записи аудита, затем искусственно изменяет одну строку. Повторный
вызов с устаревшей версией обязан вернуть `26`, оставить вторую строку без
изменений и не создать для неё аудит. После проверки временные объектные,
реестровые и аудиторские строки удаляются.
