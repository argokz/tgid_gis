# Разрезание трубопровода

Реализовано для классов `net.pipe_section` и `net.line_plain`. Разрешение
хранится в `meta.layer_catalog.can_split`; остальные линейные классы, включая
насосы и задвижки, сервер отклоняет.

## Серверный контракт

`net.split_line(table, id, expected_version, x, y)` выполняет одну атомарную
транзакцию:

1. сверяет таблицу с `net.line_reg`, доступность слоя и `row_version`;
2. блокирует исходную строку и проецирует координаты на её геометрию;
3. переиспользует активный узел того же фрагмента в пределах 1 мм либо создаёт
   `net.connect_node`;
4. создаёт два участка с прежними бизнес-атрибутами и корректными концами;
5. делит `pipesectlength` пропорционально геометрии;
6. архивирует исходную линию через `removed_at`.

Любая ошибка откатывает создание узла, линий и записи аудита. Исходная строка
не удаляется физически, поэтому история операции остаётся доступной.

## Qt

Кнопка **Разрезать линию** активна только для разрешённой сервером активной
линии, выбранной непосредственно на карте. Пользователь указывает точку и
подтверждает операцию; после обновления фрагмента открывается первый новый
участок.

Диагностический вызов без GUI:

```powershell
.\tgid_app\build\Release\tgid_app.exe `
  --split-line pipe_section:12345:123.456:789.012 `
  --expect-version 4
```

## Проверка

```powershell
psql -v ON_ERROR_STOP=1 -f sql/110_line_split.sql
psql -v ON_ERROR_STOP=1 -f sql/tests/test_line_split.sql
```

Тест выполняется внутри `BEGIN`/`ROLLBACK`: проверяет конфликт версии,
топологию новых участков, архивирование оригинала и пропорциональное деление
длины, не оставляя объектных строк в БД.

Обратная операция реализована отдельно: [безопасное соединение двух
участков](14-line-join.md).
