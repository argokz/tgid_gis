# 16 pressregulators вне net: невосстановимые сироты

После включения `regulator_press` в `LINE_PRIORITY` в `net` попали **493**
из **509** регуляторов. Оставшиеся **16** — не баг приоритета.

## Факт

У всех 16 строк в `linesobj` **оба конца NULL** (`nodeid1`/`nodeid2`):

| Почему | Число | lineid (пример) |
|---|---|---|
| null endpoints | **16** | 121, 12275, 12276, 30538, 63343–63346, 326082, 326096, 326188, 326194, 326205, 326230–326232 |

Они уже лежат в `net.line_orphan` с причиной «оба конца не найдены в nodes»
(или линия без топологии). Геометрию LineString построить нельзя.

## Совпадает ли с sety?

`read_line2` джойнит `pressRegulators` → `linesobj` → `nodes` по `nodeid1`.
Строки с пустыми концами **не читаются** ядром. На `almatygid` sety-join
видит **443** из 509; наши 493 в `net` — все линии с валидными концами
(часть sety ещё отфильтрует по `externalCodes` / `realConsumers` на
`internalNodeID` — это отдельный фильтр ядра, не миграции).

## Решение

**Не чинить конвертером** — восстанавливать нечего. Документировать как
частное `line_orphan` (см. также [05-orphan-equipment.md](05-orphan-equipment.md)).

Если заказчику понадобится сохранить атрибуты регулятора без геометрии —
они уже в `line_orphan.payload` / можно добавить слой без geom; для расчёта
это не нужно.

Полный список id подтипа: 58, 77, 78, 113, 126–129, 618, 620, 626–628, 630–632.
