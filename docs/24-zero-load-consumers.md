# Потребители с нулевой нагрузкой

Сценарий переносит команду старого ТГИД `onPotNagr0 «С нулевой нагрузкой»`.
Она находит активных потребителей, для которых расчётные нагрузки равны нулю
или не заданы.

## Исходные правила

Условие намеренно различается по типам потребителей:

- `generalizedconsumers`: ноль или `NULL` одновременно в `calchldep`,
  `calchlindep`, `calchlparall`, `calchlmix`, `calchlconseq`, `calchlpreon`;
- `realconsumers`: ноль или `NULL` только в `calchldep` и `calchlindep`.

Проверять дополнительные поля реального потребителя нельзя: это изменило бы
семантику старой команды. Внешний код остаётся обязательным из-за исходного
`INNER JOIN externalcodes`.

## Источник новой БД

Отчёт читает `net.v_nodes`, `net.v_generalizedconsumers`,
`net.v_realconsumers` и `ref.externalcodes`. Таблицы и представления `public` в
рабочем запросе не используются.

Использование `net.v_*`, а не только канонических `net.consumer_general` и
`net.consumer_real`, существенно: в БД сохранены дополнительные subtype-строки
для узлов, у которых в legacy было больше одной записи потребителя. Запрос
только по каноническим таблицам потерял бы 42 результата. Представления
сохраняют эти данные внутри новой схемы и дают точную совместимость.

На текущей БД старый и новый запросы возвращают одинаковые **1 428 строк**;
двусторонний `EXCEPT` не находит различий. Две строки относятся к legacy-узлам
без однозначного канонического класса: они видны в отчёте и CSV, но объектная
карточка для них недоступна.

## Qt и CLI

Вкладка **Нулевая нагрузка** поддерживает:

- всю БД или один фрагмент;
- поиск по внешнему коду, имени узла, потребителю и исходному ID;
- открытие канонической карточки двойным щелчком;
- экспорт полного результата (до 2 000 строк) в UTF-8 CSV.

```powershell
psql -f sql/tests/test_zero_load_consumers.sql

.\tgid_app\build\Release\tgid_app.exe --zero-load-consumers
.\tgid_app\build\Release\tgid_app.exe `
  --zero-load-consumers --zero-load-consumer-fragment 72
.\tgid_app\build\Release\tgid_app.exe `
  --zero-load-consumers --zero-load-consumer-search Абая
```

Коды завершения CLI: `0` — успех, `44` — неверный ID фрагмента, `45` — ошибка
запроса или контракта данных.
