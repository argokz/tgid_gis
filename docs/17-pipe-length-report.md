# Отчёт протяжённости трубопроводов

Перенесён первый конкретный сценарий из блока «Запросы и отчёты» старого ТГИД.
В реестре ему соответствуют `aProtNew` («Протяжённость выделенных
трубопроводов»), а также родственные команды протяжённости магистралей,
распределительных сетей, котельных и паспортного отчёта.

Новая реализация читает только `net.pipe_section`, `ref.tubingtypes`,
`ref.isolmaterials` и геометрию PostGIS.

## Параметры

- все фрагменты или один активный фрагмент;
- до 500 текущих `pipe_section`, выбранных Ctrl+щелчком на карте;
- только активные строки либо активные вместе с архивом;
- без группировки, по `diametercondit`, `tubingtypeid` или `isolmaterialid`.

Группировки перечислены в коде репозитория и не принимаются как произвольные
SQL-выражения. Для справочных групп названия берутся из схемы `ref`.

## Показатели

Для каждой группы и общего итога вычисляются:

- число участков;
- паспортная длина — `sum(pipesectlength)`;
- геометрическая длина — `sum(ST_Length(geom))`;
- рабочая длина — `sum(coalesce(pipesectlength, ST_Length(geom)))`;
- разность паспортной и геометрической длины;
- число строк с незаполненным `pipesectlength`.

Рабочая длина не теряет участок с NULL в паспорте, но отдельный счётчик делает
такую подстановку видимой для контроля качества данных.

## Qt и CSV

Вкладка **Протяжённость** показывает параметры, группы и строку `ИТОГО`.
Кнопка **Экспорт CSV** атомарно записывает UTF-8 файл с BOM и теми же строками,
включая итог. Для режима старой команды `aProtNew` сначала выделите на карте
участки одного класса, затем включите **Только выбранные на карте**.

## CLI

```powershell
# Вся активная сеть по диаметрам
.\tgid_app\build\Release\tgid_app.exe `
  --pipe-length-report diameter

# Фрагмент 86 по типам прокладки
.\tgid_app\build\Release\tgid_app.exe `
  --pipe-length-report tubing_type:86

# Конкретные участки, включая архив
.\tgid_app\build\Release\tgid_app.exe `
  --pipe-length-report none `
  --report-pipe-ids 131,133,135 `
  --report-archived
```

Группировки: `none`, `diameter`, `tubing_type`, `insulation`. Код `30` означает
ошибку CLI-параметров, `31` — неизвестную группировку или ошибку запроса.

## Проверка

На рабочей БД контрольный прогон проверяет общий итог, четыре группировки,
самый крупный фрагмент, архив и набор конкретных ID. Полученные общий счётчик и
суммы сравниваются с прямым SQL по `net.pipe_section`; неизвестная группировка,
нечисловой фрагмент, дубли и неверные ID должны быть отклонены.
