# Объём воды в тепловой сети

Сценарий переносит команду старого ТГИД `aZap1 «Объём сети»` в новый Qt-клиент
и объектную БД. Новый запрос читает только `net.pipe_section` и объектные
таблицы узлов; `public.linesobj`, `public.heatpipesections` и compat-views ему
не нужны.

## Формула и совместимость

Для каждого активного участка вычисляется:

```text
V = π / 4 × (diameterinternal / 1000)² × pipesectlength × k
```

- `diameterinternal` — внутренний диаметр в миллиметрах;
- `pipesectlength` — паспортная длина в метрах;
- `k = 2`, если `externalsignlineid = 1` (подающая и обратная трубы);
- `k = 1` для остальных признаков;
- результат измеряется в кубических метрах;
- участки, начинающиеся во внутренней схеме узла, исключаются.

Это соответствует SQL старого обработчика `GidWidget::onZap1`. При сравнении
на текущей мигрированной БД оба запроса обработали 79 337 участков и получили
`669805,5993207 м³`; расхождение составило `3×10⁻⁹ м³` из-за порядка
суммирования `double precision`.

## Возможности Qt

Вкладка **Объём сети** поддерживает:

- всю активную сеть или один фрагмент;
- только выбранные на карте `pipe_section`;
- опциональное включение архива;
- группировку по внутреннему диаметру, контуру или фрагменту;
- контроль количества строк без диаметра и паспортной длины;
- экспорт результата и итоговой строки в UTF-8 CSV.

## Диагностический режим

```powershell
.\tgid_app\build\Release\tgid_app.exe --pipe-volume-report none
.\tgid_app\build\Release\tgid_app.exe --pipe-volume-report diameter:86
.\tgid_app\build\Release\tgid_app.exe `
  --pipe-volume-report scheme `
  --report-pipe-ids 131,133,135
```

Допустимые группировки: `none`, `diameter`, `scheme`, `fragment`. Общие флаги
`--report-archived` и `--report-pipe-ids` работают так же, как в отчёте
протяжённости. Коды завершения: `0` — успех, `38` — неверные параметры,
`39` — ошибка выполнения запроса.
