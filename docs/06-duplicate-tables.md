# Шаг 17. Пары таблиц с одинаковым числом строк — разбор

Второй вопрос, вынесенный на решение заказчика: какая таблица в паре рабочая.
Закрыт проверкой содержимого и ссылок из кода.

## Исправление прежнего вывода

В [первом отчёте](01-analysis-current-db.md) я назвал эти пары «очевидными копиями».
**Это было неверно** — совпадение числа строк ещё не означает копию.

## Что показала проверка

| Пара | Строк | Колонок | Содержимое | Ссылок в коде и SQL |
|---|---|---|---|---|
| `obekty` | 38 247 | 4 | различается **полностью** | **3** |
| `tablitsa1` | 38 247 | 4 | | **0** |
| `zhile` | 7 962 | **25** | структура разная | **4** |
| `zhile1` | 7 962 | **10** | | **0** |
| `organizations` | 16 579 | 10 | структура разная | **184** |
| `organizatsii_vladeltsy` | 16 579 | 7 | | 6 |
| `spisok_ulits` | 903 | 2 | | 3 |
| `spisok_ulits_staryy` | 669 | 2 | | 3 |

Проверка содержимого `obekty` против `tablitsa1` через `EXCEPT` в обе стороны дала
по 38 247 строк с каждой — то есть **ни одна строка не совпадает**. При одинаковой
структуре это разные наборы данных, а не копия:

```
obekty:    id=1, kod=12705, zhiloy_dom=0, adres_kod=10846
tablitsa1: id=1, kod=1,     zhiloy_dom=0, adres_kod=6984
```

## Вывод по каждой паре

**`obekty` / `tablitsa1`** — рабочая `obekty`. На `tablitsa1` нет ни одной ссылки
ни в C++, ни в Python, ни в SQL-файлах приложения. Судя по имени и содержимому,
это остаток промежуточного импорта.

**`zhile` / `zhile1`** — рабочая `zhile` (25 колонок против 10). `zhile1` не
упоминается нигде: усечённая выгрузка.

**`organizations` / `organizatsii_vladeltsy`** — рабочая `organizations`,
184 ссылки против 6. Вторая используется, но заметно реже; это не дубль,
а отдельная сущность «организации-владельцы».

**`spisok_ulits` / `spisok_ulits_staryy`** — обе упоминаются, вторая по имени
и объёму (669 против 903) является предыдущей версией справочника.

## Что сделано

Все эти таблицы — справочные, вне модели сети, и в схему `net` не переносятся:
они остаются в `public` как есть. Ничего не удаляется.

Рекомендация к чистке, после согласования с эксплуатацией:

1. `tablitsa1` и `zhile1` — кандидаты на удаление, ссылок нет;
2. `spisok_ulits_staryy` — проверить, где именно она ещё используется,
   и перевести эти места на `spisok_ulits`.

Данные сначала выгрузить, удалять только после подтверждения.
