# Безопасная смена класса объекта

Контракт БД версии 12 переносит сетевой объект между совместимыми таблицами
`net` без изменения его ID. Сценарий доступен из карточки Qt кнопкой
**Изменить тип** и через `net.reclass_object` для других клиентов.

## Гарантии

- узел переносится только в другой узловой класс, линия — только в линейный;
- целевой класс должен быть опубликован и доступен для редактирования;
- ID, `fragment_id`, геометрия, топология и общие атрибуты сохраняются;
- `row_version` увеличивается на один, устаревшая версия вызывает конфликт;
- заполненные исходные поля, отсутствующие в новом классе, не отбрасываются:
  вся операция отменяется;
- изменение выполняется одной транзакцией и записывается в
  `meta.object_change_log` как `reclass`;
- история карточки остаётся доступной после перехода в другой класс того же
  геометрического типа.

Архивный объект сначала нужно восстановить. Смена между узлом и линией не
поддерживается, поскольку у них различаются реестры и топологические правила.

## Qt и диагностический режим

В интерфейсе список целевых классов строится из `meta.layer_catalog` и
серверных реестров. Сервер повторно проверяет все ограничения, поэтому прямое
изменение данных другим клиентом между открытием карточки и подтверждением не
приведёт к перезаписи.

```powershell
.\tgid_app\build\Release\tgid_app.exe `
  --reclass-object connect_node:10001:node_plain `
  --expect-version 4
```

Коды завершения: `0` — успех, `35` — неверные параметры, `36` — конфликт
версии, `37` — отказ сервера (например, риск потери поля).

## Развёртывание и тест

```powershell
psql -f sql/113_object_reclass.sql
psql -f sql/tests/test_object_reclass.sql
```

Тест внутри откатываемой транзакции проверяет смену класса узла и линии,
сохранение геометрии и связей, обновление реестров, аудит и конфликт версии.
