# tgid_app

Новый Qt6-клиент ТГИД для чистой объектной PostGIS-БД.

На первом этапе приложение:

- подключается только к схемам `net`, `ref`, `meta`;
- не использует legacy-таблицы `public.nodes` и `public.linesobj`;
- проверяет версию контракта БД и наличие SRID 9998;
- загружает `meta.layer_catalog`;
- показывает активные фрагменты сети по населённым пунктам;
- асинхронно загружает узлы и линии выбранного фрагмента;
- рисует схему с масштабированием и панорамированием;
- выбирает и подсвечивает узлы/линии щелчком мыши;
- показывает метадатную карточку атрибутов с русскими подписями и единицами;
- разделяет карточку на бизнес-, топологические и системные группы;
- загружает значения `ref` в выпадающие списки и сохраняет исходные ID;
- ищет варианты внутри больших справочников по части названия;
- проверяет и нормализует целые, дробные значения, даты и время;
- сохраняет разрешённые атрибуты напрямую в объектную таблицу `net`;
- обнаруживает параллельные изменения из QGIS/другого клиента по `row_version`
  и не перезаписывает их;
- перемещает сетевые объекты в архив и восстанавливает их без физического
  удаления строки;
- показывает общий журнал изменений из Qt, QGIS и SQL-клиентов;
- создаёт новые точечные сетевые объекты щелчком по карте;
- перемещает выбранные узлы с перестроением подключённых линий;
- меняет класс активного узла или линии с сохранением ID, геометрии,
  топологии, общих атрибутов и истории;
- создаёт линейные объекты между двумя выбранными узлами;
- разрезает выбранные `pipe_section` и `line_plain` с сохранением атрибутов;
- соединяет два последовательных `pipe_section` или `line_plain` через общий
  узел с проверкой топологии и атрибутов;
- выделяет Ctrl+щелчком несколько объектов одного класса и атомарно изменяет
  одно разрешённое поле во всём наборе;
- выполняет параметризованный поиск по любому видимому полю опубликованных
  классов, объединяет до восьми условий через AND и открывает карточку объекта;
- формирует отчёт протяжённости трубопроводов с группировками, контролем
  паспортной/геометрической длины и экспортом CSV;
- рассчитывает объём воды в сети, отдельном фрагменте или выделенных участках
  по перенесённой формуле `aZap1` и экспортирует результат в CSV;
- показывает теплопотребление и расходы последнего расчёта по всей системе,
  закрытым или открытым контурам (`aZap3–aZap5`) с экспортом CSV;
- показывает закрытых потребителей (`aZap6`), фильтрует их и открывает
  объектную карточку двойным щелчком;
- показывает потребителей с нулевой нагрузкой (`onPotNagr0`) по исходным
  правилам, с фильтрами, карточкой и CSV;
- показывает отключённых потребителей (`onPotrOtkl`), для которых отсутствует
  результат последнего расчёта фрагмента;
- не сохраняет пароль в исходниках или настройках.

## Требования

- Qt 6.8 с модулями Widgets и Sql;
- PostgreSQL-драйвер Qt `QPSQL`;
- CMake 3.24+;
- MSVC 2022 либо другой компилятор с поддержкой C++20.

## Настройка подключения

Приложение читает параметры из окружения:

```powershell
$env:TGID_HOST='localhost'
$env:TGID_PORT='5440'
$env:TGID_DB='tgid_prod'
$env:TGID_USER='tgid_app'
$env:PGPASSWORD='...'
```

Пароль не выводится в интерфейсе и журнале.

## Сборка

```powershell
cmake -S . -B build -DCMAKE_PREFIX_PATH='H:\Qt\6.8.3\msvc2022_64'
cmake --build build --config Release
```

Для запуска рядом с собранным приложением должен быть доступен Qt-плагин
PostgreSQL `sqldrivers/qsqlpsql.dll` и его клиентская библиотека `libpq`.

Проверка подключения без открытия основного окна:

```powershell
.\build\tgid_app.exe --check-db
.\build\tgid_app.exe --check-fragment 80
.\build\tgid_app.exe --check-object heat_chamber:12345
```

Приложение требует контракт БД версии 13 или новее. Для каждого поля
опубликованных таблиц должна существовать строка в `meta.field_catalog`, а все
lookup-ссылки должны вести к существующим таблицам и колонкам `ref`. В карточке
системные поля, идентификаторы, топология и геометрия доступны только для
чтения. Справочные и логические поля редактируются выпадающими списками; пункт
`NULL` очищает значение. Для обычного поля введите `NULL`. После изменения
значения нажмите **Сохранить**. Если строку успел изменить другой пользователь
или QGIS, карточка загрузит свежую версию и попросит повторить правку.
Кнопка **История** показывает версию, пользователя, приложение и изменённые
поля. Архивные объекты доступны в открытой карточке только для чтения, пока
не будут восстановлены. Вкладка **Архив** позволяет найти и открыть архивный
объект после перезапуска программы.

Диагностическая проверка записи без открытия окна:

```powershell
.\build\tgid_app.exe `
  --set-object heat_chamber:12345:memo:проверка `
  --expect-version 1
```

Архивирование и восстановление из диагностического режима:

```powershell
.\build\tgid_app.exe --archive-object heat_chamber:12345 --expect-version 2
.\build\tgid_app.exe --restore-object heat_chamber:12345 --expect-version 3
```

## Создание точечного объекта

1. Откройте фрагмент на вкладке **Карта**.
2. Выберите точечный класс в списке над картой.
3. Нажмите **Создать точку** и укажите положение объекта.
4. Подтвердите координаты.
5. Заполните открывшуюся карточку и нажмите **Сохранить**.

Диагностический эквивалент:

```powershell
.\build\tgid_app.exe --create-point heat_chamber:80:123.456:789.012
```

## Создание линейного объекта

1. Откройте фрагмент и выберите линейный класс.
2. Нажмите **Создать линию**.
3. Последовательно выберите начальный и конечный узлы.
4. Подтвердите создание и заполните карточку линии.

База запрещает одинаковые концы и узлы из разных фрагментов. При редактировании
геометрии в QGIS первая и последняя точки автоматически привязываются к
выбранным узлам. При перемещении узла база переносит концы всех связанных
активных линий. Узел со связанными активными линиями нельзя архивировать:
сначала архивируйте линии.

```powershell
.\build\tgid_app.exe --create-line pipe_section:80:10001:10002
```

## Перемещение узла

1. Выберите активный узел на карте.
2. Нажмите **Переместить узел**.
3. Укажите новое положение и подтвердите координаты.

Операция атомарно проверяет класс и `row_version` узла. Серверный триггер
перестраивает первую или последнюю точку каждой подключённой активной линии.
Изменения геометрии из Qt, QGIS и SQL фиксируются в общем журнале.

```powershell
.\build\tgid_app.exe `
  --move-node connect_node:10001:123.456:789.012 `
  --expect-version 4
```

## Смена типа объекта

1. Откройте карточку активного узла или линии.
2. Нажмите **Изменить тип** и выберите совместимый класс.
3. Подтвердите операцию; карточка откроется уже для нового класса.

База выполняет перенос в одной транзакции и сохраняет ID, геометрию, связи
линий, общие атрибуты и непрерывную историю. Узел нельзя превратить в линию и
наоборот. Если в исходном классе заполнено поле, которого нет в целевом,
операция откатывается без потери данных. `row_version` защищает от параллельной
правки в Qt, QGIS или SQL-клиенте.

```powershell
.\build\tgid_app.exe `
  --reclass-object connect_node:10001:node_plain `
  --expect-version 4
```

## Разрезание трубопровода

1. Выберите на карте активный `pipe_section` или `line_plain`.
2. Нажмите **Разрезать линию**.
3. Укажите место разрезания и подтвердите операцию.

База атомарно проверяет `row_version`, проецирует указанную точку на линию,
создаёт либо переиспользует соединительный узел, переносит атрибуты в два новых
участка и архивирует исходную строку. `pipesectlength` делится пропорционально
геометрии. Насосы, задвижки и другое линейное оборудование разрезать нельзя.

```powershell
.\build\tgid_app.exe `
  --split-line pipe_section:12345:123.456:789.012 `
  --expect-version 4
```

## Соединение трубопроводных участков

1. Выберите на карте первый активный `pipe_section` или `line_plain`.
2. Нажмите **Соединить линии**.
3. Щёлкните по второму участку того же класса и подтвердите операцию.

Участки должны иметь ровно один общий активный `connect_node`, одинаковые
бизнес-атрибуты и принадлежать одному фрагменту. В общем узле не должно быть
других активных линий. База атомарно создаёт объединённую геометрию, суммирует
`pipesectlength`, архивирует оба исходных участка и общий узел. Проверки
`row_version` защищают от одновременной правки в Qt или QGIS.

```powershell
.\build\tgid_app.exe `
  --join-lines pipe_section:12345:4:12346:2
```

## Массовое редактирование

1. Удерживая Ctrl, выберите на карте от 2 до 500 объектов одного класса.
2. Нажмите **Массово изменить**.
3. Выберите редактируемое поле из `meta.field_catalog`, задайте значение или
   отметьте **Установить NULL**.
4. Подтвердите число объектов и новое значение.

Репозиторий перечитывает версии выбранных строк и выполняет один
параметризованный `UPDATE` в транзакции. Если QGIS или другой клиент изменил,
архивировал либо удалил хотя бы один объект, откатывается вся пачка. Системные,
топологические поля и идентификаторы недоступны. Обычные триггеры создают запись
истории для каждого успешно изменённого объекта.

```powershell
.\build\tgid_app.exe `
  --batch-set pipe_section:memo:проверка `
  --batch-objects 12345:4,12346:2
```

## Поиск объектов

Вкладка **Поиск** использует `meta.layer_catalog` и `meta.field_catalog`:

1. выберите класс и поле;
2. задайте операцию — содержит, равно, больше, меньше, между, заполнено или не
   заполнено;
3. нажмите **Добавить условие** и повторите шаги для других полей (до восьми);
4. при необходимости удалите условие из таблицы или включите архив;
5. нажмите **Найти** и дважды щёлкните результат, чтобы открыть карточку.

Все добавленные условия объединяются через `AND`. Если таблица условий пуста,
кнопка **Найти** выполняет текущее условие, как в прежнем интерфейсе.

Один запрос возвращает не более 200 строк. Имена таблиц и полей проходят
проверку каталога и экранирование драйвером, значения передаются параметрами.
Поиск не использует legacy-таблицы или mega-JOIN.

```powershell
.\build\tgid_app.exe `
  --search-objects pipe_section:location:contains `
  --search-value Абая

.\build\tgid_app.exe `
  --search-objects pipe_section:diametercondit:between `
  --search-value 100 `
  --search-second-value 300

.\build\tgid_app.exe `
  --search-objects pipe_section `
  --search-condition 'diametercondit|greater|100' `
  --search-condition 'diametercondit|less|300' `
  --search-condition 'location|contains|Абая'
```

## Отчёт протяжённости трубопроводов

Вкладка **Протяжённость** формирует отчёт непосредственно по
`net.pipe_section`. Можно выбрать один фрагмент, всю базу либо текущие участки,
выделенные Ctrl+щелчком на карте. Доступны группировки по условному диаметру,
типу прокладки и материалу изоляции.

Для каждой группы выводятся число участков, паспортная длина,
`ST_Length(geom)`, рабочая длина с геометрической подстановкой при NULL,
расхождение и количество незаполненных паспортных длин. Результат экспортируется
в UTF-8 CSV.

```powershell
.\build\tgid_app.exe --pipe-length-report diameter
.\build\tgid_app.exe --pipe-length-report tubing_type:86
.\build\tgid_app.exe `
  --pipe-length-report none `
  --report-pipe-ids 131,133,135
```

## Объём сети

Вкладка **Объём сети** переносит старую команду `aZap1`. Можно рассчитать всю
сеть, один фрагмент либо выбранные на карте `pipe_section`, сгруппировать
результат по внутреннему диаметру, контуру трубопровода или фрагменту и
экспортировать таблицу в UTF-8 CSV.

Для каждого участка используется формула:

```text
V = π / 4 × (diameterinternal / 1000)² × pipesectlength × k
```

Здесь диаметр задан в миллиметрах, длина — в метрах, результат — в м³;
`k = 2` для общего подающего и обратного контура (`externalsignlineid = 1`) и
`k = 1` для остальных признаков. Как в старом ТГИД, участки внутренних схем не
включаются. Таблица отдельно показывает строки без внутреннего диаметра или
паспортной длины.

```powershell
.\build\tgid_app.exe --pipe-volume-report none
.\build\tgid_app.exe --pipe-volume-report diameter:86
.\build\tgid_app.exe `
  --pipe-volume-report scheme `
  --report-pipe-ids 131,133,135
```

## Теплопотребление последнего расчёта

Вкладка **Теплопотребление** переносит команды `aZap3–aZap5`. Для каждого
фрагмента выбирается запись с максимальным `calc.calculation.id`, после чего
агрегируются активные узлы из соответствующего `calc.pt_out`.

Режимы отчёта:

- **Все системы** — семь показателей `aZap3`;
- **Закрытые системы** — зависимое и независимое отопление, вентиляция и
  закрытое ГВС (`aZap4`);
- **Открытые системы** — ГВС из подачи, обратки и рециркуляция (`aZap5`).

Для каждого показателя отдельно выводятся нормативное теплопотребление в
`Гкал/ч` и фактический массовый расход в `т/ч`. Можно выбрать один фрагмент или
все фрагменты, для которых есть результаты. Таблица экспортируется в UTF-8 CSV.

```powershell
.\build\tgid_app.exe --heat-consumption-report all
.\build\tgid_app.exe --heat-consumption-report closed:2
.\build\tgid_app.exe --heat-consumption-report open:1
```

## Закрытые потребители

Вкладка **Закрытые потребители** переносит старую команду `aZap6`. В список
попадают активные `consumer_real` и `consumer_general` со значением
`consumerstateid = 2`. Можно выбрать фрагмент и искать по внешнему коду, имени
узла, имени потребителя или исходному ID. Двойной щелчок открывает обычную
редактируемую карточку объекта, результат экспортируется в UTF-8 CSV.

Названия кодов читаются из `ref.externalcodes`. Поле `externalcodeid` во всех
узловых классах получило lookup-редактор и настоящий внешний ключ, поэтому Qt
и QGIS не смогут сохранить несуществующий код.

```powershell
.\build\tgid_app.exe --closed-consumers
.\build\tgid_app.exe `
  --closed-consumers `
  --closed-consumer-fragment 72
.\build\tgid_app.exe `
  --closed-consumers `
  --closed-consumer-search Абая
```

## Потребители с нулевой нагрузкой

Вкладка **Нулевая нагрузка** переносит команду `onPotNagr0`. Для обобщённых
потребителей нулевыми или незаданными должны быть `calchldep`, `calchlindep`,
`calchlparall`, `calchlmix`, `calchlconseq` и `calchlpreon`. Для реальных
потребителей старый запрос проверял только `calchldep` и `calchlindep`; это
поведение сохранено без расширения условия.

Доступны выбор фрагмента, текстовый поиск, открытие объектной карточки и экспорт
UTF-8 CSV. Дополнительные subtype-строки учитываются через представления `net`,
поэтому результат полностью совпадает со старым запросом. Строки без
канонического класса отображаются и экспортируются, но карточка для них не
открывается.

```powershell
.\build\tgid_app.exe --zero-load-consumers
.\build\tgid_app.exe `
  --zero-load-consumers `
  --zero-load-consumer-fragment 72
.\build\tgid_app.exe `
  --zero-load-consumers `
  --zero-load-consumer-search Абая
```

## Отключённые потребители по расчёту

Вкладка **Отключённые потребители** переносит команду `onPotrOtkl`. В список
попадает активный реальный или обобщённый потребитель, если для его узла нет
строки в `calc.pt_out` последнего расчёта соответствующего фрагмента.

Интерфейс различает две причины: у фрагмента вообще нет расчёта либо последний
расчёт есть, но результата этого узла в `PT_OUT` нет. Доступны выбор фрагмента,
поиск, открытие канонической карточки и UTF-8 CSV. Из-за большого глобального
списка за один запрос показывается до 5 000 строк; для полного разбора следует
выбирать конкретный фрагмент или задавать фильтр.

```powershell
.\build\tgid_app.exe --disconnected-consumers
.\build\tgid_app.exe `
  --disconnected-consumers `
  --disconnected-consumer-fragment 72
.\build\tgid_app.exe `
  --disconnected-consumers `
  --disconnected-consumer-search Абая
```
